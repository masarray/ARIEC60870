Why it exists

Because many protocol problems are visible in the frames long before they are clear in SCADA.

A link can be alive while the application data is silent. A command can be correct but delayed by Class 1 congestion. A device can answer but use a different Common Address. ARIEC60870 keeps those details close to the engineer instead of hiding them behind a single pass/fail label.

Protocol flow

ACD is not just a bit. It changes what the master should do next.

In IEC-101 unbalanced communication, the master does not normally hammer Class 1 forever. It polls regular traffic, watches the secondary response, and drains Class 1 when the outstation says urgent data is waiting.
