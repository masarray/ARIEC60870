Troubleshooting

Practical checks for no response, GI gaps, command issues, and frame trace findings.

Use the checklist to separate physical link problems, addressing problems, protocol state problems, and mapping/reporting problems before escalating to vendor or site teams.

Download latest release Open GitHub repository

No response

Start with transport and addressing before assuming the protocol decoder is wrong.

  • Check COM port, baud rate, parity, stop bits, and RS-485 direction for IEC-101/103.
  • Check IP address, port, firewall, and TCP reachability for IEC-104.
  • Confirm link/common address matches the device configuration.

GI does not drain expected data

GI can fail because of addressing, device profile, or polling policy mismatch.

  • Verify COT and common address in frame trace.
  • Watch ACD/DFC and Class 1/Class 2 activity for serial links.
  • Compare received Type IDs or FUN/INF against the project mapping profile.

Values appear without readable names

Protocol decode and user naming are separate.

  • Load a JSON mapping profile.
  • Check IOA or FUN/INF keys.
  • Keep project signal naming user-owned and version-controlled.

Report looks incomplete

The report reflects the session evidence currently available.

  • Run the session long enough for GI and event drain.
  • Check Diagnostics and Findings.
  • Use raw Frame Trace when the high-level evidence is not enough.
