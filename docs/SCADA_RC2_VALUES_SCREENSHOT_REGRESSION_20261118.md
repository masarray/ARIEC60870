## Explicit engineering limits

- For the proposed Q TwoPoint, `Y = -2078 + (X + 32768) * (4156/65535)`. Because signed X endpoints are asymmetric, **X=0 maps to ~+0.03170825 MVar**, not exactly zero; X=13641 maps to ~865.09612 MVar. Verify zero behavior and Q range against the *actual* SCADA mapping; never silently force symmetric endpoints or clip source QDS OV/IV. Alternate Q Lab maps the same X to ±260 if field evidence supports it.
- Operator-confirmed POAQ feedback **1200** is display-only TI9 normalized mapping: `X=32767/32768 → 1199.96337890625`. A received `OV` remains **OV**, not Good; exceeding the measuring type's representable maximum is not proof of calibration error. **POOP TI48 command stays 0..1000**, no encoder or permission changes.
- The corrected bundled file is a **future release candidate site reference**. **The already-published immutable v3.6.17-rc.2 binary does not contain these fixes.** Updating GitHub source cannot rewrite the existing installed JSON, especially when saved preferences load an older custom profile. The operator must install a new qualified candidate and deliberately activate the updated profile.
- No physical SCADA/RTU source frames or authoritative database export were supplied with the screenshots. An unexpected IOA does **not** establish an IEC ASDU decoder bug; confirm 3-byte little-endian IOA, configured widths, SQ/VSQ and original HEX before adding a mapping or changing a parser.
