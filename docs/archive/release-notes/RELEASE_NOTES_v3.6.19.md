## IEC-101: source-backed Class-1 pending indication in the Events COT column

The former buffer classifier first used an absolute RTU-to-PC clock difference and then required RTU event time to advance much faster than host RX time. Both were insufficient: a time-zone difference can cause permanent false positives, while a real 1200-bps Class-1 queue can drain at an ordinary event-time rate and be missed.

- On a **verified original IEC-101 FC10 Class-1 poll → matching FC8 secondary user-data response**, ArSee reads the secondary `ACD` access-demand bit. `ACD=1` makes that received event's COT display `3 · spontaneous (buffer)`; `ACD=0` immediately removes the suffix for the new event.
- **Meaning:** `(buffer)` is a compact operator **Class-1 data still pending** cue *at that particular RTU response*. IEC-101 does **not** provide a universal per-event FIFO-origin bit. Neither `ACD=1` nor its transition to zero independently proves the generation age or persistent FIFO storage of any one event. ACD=0 is not a physical FIFO integrity/overflow certificate.
- The original `COT=3` is never rewritten, no new Delivery grid column is added, and each decision and its evidence basis are preserved with the individual event in the indexed history/exports. Multi-object ASDUs share one verified original physical response and do not fabricate additional independent polls.
- Mismatched source/Link A–B, FC11 Class-2 replies, invalid frames and unproven TX/RX pairing cannot supply an IEC-101 Class-1 queue claim. Where exact ACD evidence is unavailable, analysis remains conservative and independent of absolute RTU/PC clock offsets. Actual master polling, FCB, serial RX/TX, control, GI and redundancy ownership have **not** been changed by the buffer-display fix.

**Operator field observation (single real IEC-101 RTU, November 21):** a screenshot of the current source build shows 777 retained events with `3 · spontaneous (buffer)` for one series of FC10 responses, automatically returning to `3 · spontaneous` on a subsequent response, with ordinary FC11 background measurements interleaved. No issues are indicated in that observed screenshot. This is useful **single-device UI/communication evidence**, *not* independently archived byte-for-byte ACD proof, a 2,000-event lossless soak or multi-vendor interoperability certification.

## Connection-profile and cockpit corrections

- Isolated IEC-101 address/field-width persistence from IEC-103 defaults so that switching protocols cannot silently replace a working IEC-101 2-octet Link/CA/COT and 3-octet IOA configuration. Uncertain migrated settings require operator verification before active communication; a 1-octet configuration remains legal where explicitly chosen.
- Refined IEC-104 Connection Setup height and placement of advanced APCI controls to reduce unnecessary scrolling while retaining accessible detailed settings.
- Removed intrusive Frame Details hover tooltips, reduced Connection Setup close-button size and improved restrained WPF panel geometry.
- Improved healthy/degraded dual-link status presentation and source-qualified timeline facts without changing the underlying Class-1/Class-2 or active/standby logic.
- Made command select/execute and feedback more readable and better distinguished proven protocol confirmations from physical breaker/IED action; commands remain operator-authorized and source-bound.

## Windows installer and upgrades from v3.6.17/v3.6.18

- Official release artifacts use `ArSee-v3.6.19-setup-win-x64.exe`, `ArSee-v3.6.19-win-x64.zip`, an SPDX SBOM, and `SHA256SUMS.txt`; public release provenance is generated by the packaging workflow.
- An existing *registered legacy program installation* under `%LOCALAPPDATA%\Programs\ARIEC60870` is moved to the canonical `%LOCALAPPDATA%\Programs\ArSee` using the verified previous Inno uninstaller and the **direct official installer**, with collision/missing-registration checks that fail closed rather than deleting unknown files.
- Existing canonical ArSee installations continue to update in place. Existing custom installation paths are not silently moved. A legacy-folder installation **cannot** safely be relocated by the previous in-app update worker; run the new official setup **directly**, after closing active IEC sessions and saving captures.
- This migration replaces old **program binaries**, but deliberately preserves the distinct user-owned `%LOCALAPPDATA%\ARIEC60870` workspace containing signal lists, profiles, settings, evidence and updater records. Do **not** manually delete that folder or uninstall your previous installation before following the direct-upgrade procedure. The move is not a fully transactional binary rollback if power is lost during the brief uninstall→install interval.
- The portable release is a self-contained Windows x64 .NET publish and does not require installing a separate .NET Desktop runtime in advance. Windows/COM drivers, permission policies and site-specific hardware prerequisites remain the operator's responsibility. No blanket claim is made that arbitrary missing third-party VC++ runtimes or serial drivers are installed automatically.

Confirm SHA256 before running setup.

Perform commands and timing tests only on authorized, isolated equipment. Preserve raw RX evidence for any event-buffer dispute.
