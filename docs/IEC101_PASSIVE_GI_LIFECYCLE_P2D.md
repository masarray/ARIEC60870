# ARIEC60870 IEC-101 P2D — Passive GI Lifecycle & Evidence Timeline

Date: 2026-10-28. Based on merged P0/P1/P2A/P2B/P2C in `master` `943bd87d88cf83f41243e07bd24c2aabe950b062`. Parent issue #30; record as a clean-room protocol implementation.

## Objective

An ASE2000-class IEC-101 passive observer must show the **sequence** of General Interrogation, not just a decoded ASDU Type ID and a rolling trace. A field engineer needs to see whether an RTU confirmed GI, sent interrogated data and terminated it, without confusing a missing capture fragment with a proven failure.

P2D adds a deterministic bounded GI lifecycle state machine that uses exact raw-frame source offsets, stores every lifecycle event to disk, and integrates into the **existing** Frame Trace and Findings. No new window/tab/toolbar; no requests/transmits/port ownership.

## Wire-accurate classification

- GI activation: master-to-RTU ASDU Type ID **100**, COT **6** (Activation), one information object with IOA=0 and QOI; all configured widths (Link Address 0/1/2, COT1/2, CA1/2, IOA1/2/3) must match the original signal.
- RTU ACTCON: Type ID 100 / COT **7**, positive or P/N negative. Negative ends the observed request as rejected, not completed.
- Interrogated data: RTU-originated *non-100* ASDU with COT **20..36**, matched to CA/OA and GI group QOI; count frames, emit only the first data frame for bounded output rather than flooding GUI.
- RTU ACTTERM: Type ID 100 / COT **10** with matching CA/OA/QOI closes the lifecycle; not guessed from an ACK or timer.
- A new activation while another is pending is reported as `RepeatedActivation` for an identical request or `Superseded` for a different QOI, not silently treated as success.
- ACTCON/ACTTERM without a recorded matching request is `UnmatchedResponse`, not an unconditionally failed RTU.
- Timeouts apply after the configurable *estimated host reception* window (default 120s), and only when advancing through later observed traffic or explicit final-time calculation. At capture EOF an incomplete GI becomes `PendingAtCaptureEnd`, not a fabricated timeout.
- GI Type ID 100 control must use VSQ=1, IOA=0 and an exactly sized QOI. Invalid-checksum frames, malformed ASDUs and corrupt headers do not change GI state.

**Observability limit:** Two RX COMs monitor one full-duplex serial circuit, not both redundant links. GI during a 30-second suspected failover is *not* evidence that a switch occurred. The NUC role/timestamp and opposite physical line are external evidence. USB read-completion timestamps cannot prove bit-level line gaps.

## Architecture and performance

```
SCADA TX RX-1 + RTU TX RX-2 → single raw journal writer (authoritative)
  ├── FT1.2 scanner per direction → existing P2B transaction correlator → transactions.jsonl
  ├── pure PassiveIec101GiTracker → gi-events.jsonl (unbounded disk log, bounded per-frame output)
  └── bounded nonblocking UI event ring → existing Frame Trace / Findings
Verified raw journal replay → same pure GI tracker → same Frame Trace / Findings
```

`PassiveIec101GiTracker` lives in `ARIEC60870.Monitor`, with **no WPF, Active Master, hardware or timers**. State is bounded by configurable maximum GI sessions (default 64), keyed by physical request stream + common address + originator, and tracks QOI. If this limit is reached, old pending sessions are explicitly evicted with raw-offset evidence, never silently lost.

The writer serializes all derived GI events to `gi-events.jsonl`, independent of the 256-item dropping UI preview. These derived indexes are disposable; the same record can be regenerated by `PassiveJournalReplay.ReadVerifiedFrames` from *verified binary journal streams*. Data bytes in the original manifest and journals must never be rewritten for analysis. There is no blocking `Dispatcher.Invoke` on serial RX and no WPF object in the Monitor engine.

The existing Frame Trace row for a GI event includes phase, CA, QOI, data-frame count, request stream and original byte offset. Findings show only exceptional evidence (negative confirmation, repeated/overlapping GI, timeout or unmatched response); a normal GI lifecycle does not flood the diagnostic queue. IEC-101 GI is *not falsely injected as a relay SOE event* into the data Event Log.

## Acceptance cases and instrumentation

1. ACT 100/6 → ACTCON 100/7 → interrogated COT20 data → ACTTERM 100/10: one correlated lifecycle, exact raw references, bounded live UI.
2. Negative ACTCON and orphan ACTTERM: rejected/unmatched, not completed.
3. Duplicate activation/overlapping group interrogation: explicit evidence with QOI.
4. ACTTERM absent: `TimedOut` if the configured elapsed observation window passed; otherwise `PendingAtCaptureEnd`.
5. Bad checksum/wrong CA/QOI or malformed GI control: never advances a matching request.
6. Two-octet link address and non-default COT/CA/IOA widths.
7. Full raw journal writer → saved derived GI events, deletion of derived indexes → verified offline recomputation with identical lifecycle kinds, streams and raw offsets.
8. Real Windows WPF MainWindow GUI smoke verifies the GI sequence appears in **existing Frame Trace** and is neither hidden nor sent to any active Master.
9. Warnings-as-errors Release, 19/19 protocol smoke, all xUnit, CodeQL/dependency/hygiene, self-contained Windows GUI ZIP + SHA.
